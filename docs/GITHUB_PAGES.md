# Размещение frontend на GitHub Pages

Frontend — статические файлы без сборки. Всё делаете вы; я ничего не публикую.

## 1. Подготовка файлов

1. В `frontend/js/config.js` укажите `API_BASE` — адрес вашего Worker (см. [CLOUDFLARE.md](CLOUDFLARE.md)), без слэша на конце.
2. Заполните `frontend/impressum.html` и `frontend/datenschutz.html`: всё в квадратных скобках замените своими данными и удалите жёлтые подсказки. Публичный сайт в Германии без Impressum запускать нельзя; текст при сомнениях покажите юристу.

## 2. Репозиторий

GitHub Pages умеет отдавать сайт только из **корня** ветки или из папки **/docs**. Поэтому содержимое папки `frontend/` нужно положить в корень репозитория (или в `docs/`), а не оставлять вложенной.

Вариант A: отдельный репозиторий только для сайта: скопируйте в него содержимое `frontend/` (файлы `index.html`, `css/`, `js/` и т.д. лежат в корне).

Вариант B: монорепозиторий: переименуйте `frontend` в `docs`, backend оставьте рядом.

## 3. Включение Pages

Репозиторий → Settings → Pages → Build and deployment → Source: «Deploy from a branch» → ветка `main`, папка `/ (root)` или `/docs` → Save. Через минуту сайт будет по адресу `https://<логин>.github.io/<репозиторий>/`.

Все пути в проекте относительные (`css/style.css`, `sw.js`, `manifest.webmanifest`), поэтому работа из подпапки `/репозиторий/` поддерживается.

## 4. После публикации

1. В `backend/wrangler.toml` в `ALLOWED_ORIGINS` поставьте `https://<логин>.github.io` (origin без пути) и выполните `npx wrangler deploy`.
2. Откройте сайт на телефоне: «Добавить на главный экран» (iOS: «Поделиться» → «На экран Домой»; Android/Chrome: меню → «Установить приложение»).
3. `admin.html` доступна по адресу `…/admin.html`. Она закрыта токеном и помечена `noindex`, но ссылка публична — токен держите в секрете.

## 5. Telegram Mini App

В @BotFather: `/newbot` (если бота нет) → `/newapp` или кнопка меню бота → укажите URL сайта (`https://…github.io/…/`). Приложение определяет Telegram по параметрам запуска и вызывает `Telegram.WebApp.ready()/expand()`. Отдельной настройки в коде не требуется.

## 6. Обновление сайта

Правки файлов → commit и push вами. Service worker использует стратегию «сначала сеть», поэтому новые версии подхватываются без ручной очистки кэша. Если меняете состав файлов оболочки, увеличьте `VERSION` в `sw.js`.

## 7. Свой домен и приватность

Leaflet и markercluster подгружаются с cdnjs, тайлы с tile.openstreetmap.org: при этом IP посетителя уходит этим сервисам (это указано в Datenschutz). Если хотите убрать внешнюю подгрузку скриптов, скачайте файлы библиотек в репозиторий и поменяйте пути в `index.html`. Для заметной нагрузки на тайлы OSM используйте собственного поставщика тайлов (политика OSM допускает только умеренное использование).
